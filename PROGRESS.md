## Этап 1 — Данные

**Статус: ЧАСТИЧНО. Код готов, реальные данные НЕ скачаны — сеть закрыта.**

### Что с сетью (зафиксировано)

Среда исполнения (Claude Code on the web, изолированный контейнер) выпускает HTTPS
только через агент-прокси с политикой сети. Все биржевые хосты закрыты на уровне
шлюза:

| Хост | Результат |
|---|---|
| `data.binance.vision:443` | `CONNECT tunnel failed, 403` (policy denial) |
| `fapi.binance.com:443` | `CONNECT tunnel failed, 403` |
| `api.bybit.com:443` | `CONNECT tunnel failed, 403` |

Проверено через `curl` и подтверждено в `$HTTPS_PROXY/__agentproxy/status`
(`recentRelayFailures` → `connect_rejected` по всем трём). `pypi.org` открыт
(поэтому pandas/numpy/scipy поставились), биржи — нет.

Альтернатива, которую проверил: подключённый MCP-сервер Crypto.com отдаёт свечи,
но **максимум 50 баров** на запрос (`get_candlestick` → "returns up to 50").
Для 4 лет истории по 5 инструментам это непригодно. Отброшено.

**Вывод: реальные данные грузит трейдер локально. Код загрузчика написан и готов.**

### Что построено

`download_data.py` — расширенный загрузчик (заменяет `download_h1_data.py`,
старый файл оставлен нетронутым):

- ТФ **H1 / H4 / D** (было только H1);
- **bulk-режим `data.binance.vision`** (р.5.2): помесячные zip-дампы
  `data/futures/um/monthly/klines/<SYM>/<TF>/`, докачка дневными файлами за
  текущий месяц, сборка в один CSV, проверка контрольных сумм `.CHECKSUM`;
- **ccxt-режим** (р.5.3) как резерв/дозагрузка свежего хвоста, Bybit и Binance;
- **загрузка funding history** (р.5.5): bulk `fundingRate` + ccxt
  `fetchFundingRateHistory`;
- **проверки качества р.5.6** прямо в загрузчике: пропуски баров, дубли
  таймстампов, единый UTC, монотонность, целостность OHLC
  (`low ≤ open,close ≤ high`), нулевые объёмы, отсечение незакрытой свечи;
- отчёт таблицей по каждому инструменту/ТФ.

Запуск (у трейдера, где есть сеть):

```bash
pip install pandas numpy requests ccxt
python download_data.py --source bulk --tf 1h 4h 1d --start 2022-01 --funding
python download_data.py --source ccxt --exchange bybit --tf 1h 4h 1d   # для форварда
python download_data.py --check-only                                   # только проверки качества
```

Файлы кладутся в `./data/` как `BINANCE_BTCUSDT_1h.csv`,
`BINANCE_BTCUSDT_funding.csv` и т.д. Движок читает ровно этот формат.

### Данные-заглушки для разработки

Так как реальных данных нет, для отладки движка и **калибровки фильтра**
сделан генератор `crypto_strat/data/synthetic.py`. Он умеет два режима:

- `edge` — в цену зашит **настоящий** persistent-momentum (скрытая марковская
  цепь режимов с дрейфом) → у пробойной стратегии есть реальная положительная
  ожидаемость;
- `noise` — чистое GBM без структуры → эджа нет вообще, ни у кого.

Это нужно НЕ для оценки стратегий, а для проверки самого фильтра
(см. Этап 4). Любая метрика стратегии на синтетике **не имеет ценности**
и так и помечена в отчётах.
